== v2.1.1.5 — 2026-09-29

* Fix an infinite loop (100 % CPU, `convert` never returned) on a line starting with `|` that was not the header of a table with a separator row, e.g. `x| A | b |` followed by `| N | c |`, or a table row after a text line. The paragraph parser refused such a line without consuming it, so the main loop never advanced. Same cause for `#foo` (no space) and an indented `  > quote`.
* The paragraph parser now always consumes its first line, and the main loop raises instead of looping if a block consumes nothing.
* Tables closer to kramdown: inside a table, any non-blank line containing a pipe is a row (e.g. `{% if x %}| a | b |`); a row without separator row becomes a headerless table (`[%noheader,cols=N*]`); rows are padded with empty cells so that Asciidoctor drops no cell.
* Blockquotes indented by up to 3 spaces are recognised.
* Non-regression specs `spec/termination_spec.cr`, run in a child process killed after 5 s (`ConversionGuard`) so that a regression fails instead of hanging the suite.

== v2.1.1.2 — 2026-04-23

Integration test suite for the Markdown → AsciiDoc pipeline, on top
of the existing per-element unit specs. Realistic README-shaped
fixtures are round-tripped through `KramdownAsciidoc.convert` and
`convert_file`, and the AsciiDoc output is checked for structural
markers (headings, fenced blocks, links, lists, quotes, thematic
breaks) and document invariants (paragraph separation, determinism,
no stray Markdown markers).

* 3 new spec files under `spec/integration/`: **sanity** (empty
  docs, trailing newline, no stray `**bold**`), **full_document**
  (README fixture → AsciiDoc with expected markers + file-based
  `convert_file`), **structure** (paragraph separation, heading
  ordering, list formatting, determinism). **13 integration tests,
  32 unit tests, 45 total — all green.**
* New helper `IntegrationHelper` in `spec/integration/spec_helper.cr`
  with `convert`, `fixture` and `convert_to_tempfile` primitives,
  plus a `spec/integration/fixtures/readme.md` test asset.
